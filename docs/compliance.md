# 合规与国产化销售指南

面向「作为国产数据库销售」的合规准备材料。**结论先行:软件本体已具备销售条件(原创引擎、宽松许可免费商用、依赖全部合规);「国产数据库」身份宣称还需仓库之外的法定动作(销售主体、软件著作权登记、按需测评认证)——本文逐项给出仓库内已备齐的依据与仓库外待办清单。**

## 自主可控声明与依据

| 事实项 | 依据 |
|---|---|
| **原创内核,非衍生发行版** | 存储引擎(pager/WAL/B+树/heap)与 SQL 内核全部为自研 Rust 实现,不 fork、不内嵌、不翻译自 MySQL/PostgreSQL/SQLite 或任何既有数据库代码;代码原创性以本仓库完整提交历史为证 |
| **无闭源组件** | 全部源码开源(本仓库),无任何闭源 SDK、黑盒组件或授权模块 |
| **运行时零外部依赖** | 交付物为静态链接二进制(Linux glibc-static / macOS);服务器进程不回连任何外部服务(无遥测、无 License Server、无云端鉴权),离线环境可完整运行 |
| **依赖供应链合规** | 全部第三方依赖为宽松许可(MIT/Apache-2.0/BSD/ISC/BSL-1.0/Unicode-3.0),无 GPL/AGPL/LGPL 传染义务,逐包清单见[第三方依赖许可审计](third-party-licenses.md) |
| **密码学自持** | 认证哈希(PBKDF2-HMAC-SHA256)、AES-256-GCM 帧加密、Web 控制台口令散列为**仓库内实现**(零第三方加密依赖);TLS 走 rustls(纯 Rust,无 OpenSSL 交叉编译负担) |
| **开发基础设施** | 开发/CI 托管于 GitHub(GitHub Pages/GHCR 分发),属开发与分发渠道,不影响产品交付物的自主性;内网环境可用 release 二进制 tar 包或源码构建,完全不依赖境外服务 |

## CPU 与操作系统支持矩阵(信创硬件适配)

### 官方预构建(镜像 + 二进制,CI 逐版发布)

| CPU 架构 | 代表平台 | 支持 | 交付物 |
|---|---|---|---|
| x86_64 | 海光(Hygon)、兆芯(Zhaoxin)、Intel/AMD | ✅ 官方 | Docker 镜像 `linux/amd64`;二进制 `docsql-<ver>-x86_64-unknown-linux-gnu.tar.gz`(glibc 静态链接,无动态库依赖) |
| ARM64 | 鲲鹏(Kunpeng 920)、飞腾(FT-2000+/S2500)、Apple Silicon | ✅ 官方 | Docker 镜像 `linux/arm64`;二进制 `docsql-<ver>-aarch64-unknown-linux-gnu.tar.gz` |
| loongarch64 | 龙芯(3A5000/3A6000) | ⚠️ 源码构建 | 见下「龙芯适配路径」 |

### 操作系统

Linux 交付物为**静态链接二进制**(镜像运行层 `FROM scratch`,无 shell/libc 之外的任何基础 OS 组件),不依赖发行版 glibc 版本:

- **国产 OS**:麒麟(银河麒麟/中标麒麟)、统信 UOS、openEuler、Anolis OS、龙蜥等均可直接运行(容器或裸机);
- 其他 Linux 发行版无版本约束;macOS(x86_64/arm64)有官方二进制(嵌入式/开发形态);
- Windows:服务器无预构建(可源码编译);.NET 客户端/驱动栈跨平台,Windows 上连远程服务为支持形态。

### 龙芯适配路径(loongarch64)

Rust 工具链原生支持 `loongarch64-unknown-linux-gnu` 目标(Tier 2),源码构建:

```bash
rustup target add loongarch64-unknown-linux-gnu
cargo build --release --target loongarch64-unknown-linux-gnu -p docsql-server -p docsql-cli
```

(需 loongarch64 交叉链接器或目标机编译;官方 CI 暂未包含该目标——引入需可复现的容器基础镜像,待部署验证后加入发布矩阵。)

## 商业模式说明(双许可的合规使用)

Apache-2.0 / MIT 双许可均为宽松许可,对**下游销售者**的含义:

- 可直接闭源集成、打包销售、提供商业服务,无需支付授权费或公开自己的商业代码;
- 唯一义务:分发时保留 LICENSE-APACHE / LICENSE-MIT 文件与版权声明(即"保留声明"而非"开放源码");
- 若以开源方式二次分发修改版,须遵守所选许可(附许可文本、声明变更);
- **品牌与开源社区版的关系建议**:商业化主体注册商标后,商标仅约束"以 DocSQL 名义销售"的行为,不收回既有开源版本的许可;商业版与社区版可用品牌区分(如企业版命名),这是双许可数据库产品的常规做法(MySQL/PostgreSQL 生态先例)。
